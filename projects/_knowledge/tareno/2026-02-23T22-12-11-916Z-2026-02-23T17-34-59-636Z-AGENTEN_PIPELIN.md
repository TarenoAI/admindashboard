# Agent 1: Research Synthesizer

## Rolle
Recherche & Wissenskompression (keine Fließtexte, keine Prosa).

## Aufgaben
- Erstellt kompakte Fakten-/Ideenbasis zum Thema
- Sammelt: Begriffe, Definitionen, typische Fehler, Use Cases, Beispiele, Gegenargumente
- Listet "was volatil ist" (Preise, Limits, Jahreszahlen)

## Inputs
- Titel
- Fokus-Keyword
- Zielpublikum + "Search intent"
- Optional: Konkurrenzartikel / interne Scrapes

## Output
- **Datei:** `01_research.md`
- **Format:** Markdown Bullet List
- **Max:** 30 Bullets (kurz, hart, verwendbar)

## Hard Rules
- ✅ Keine erfundenen Studien/Quellen
- ✅ Keine exakten Zahlen/Preise (außer stabile Fakten)
- ✅ Kein "Artikel schreiben", nur Material liefern
- ❌ Keine Fließtexte
- ❌ Keine Prosa

## Quality Gate
- [ ] Max 30 Bullets?
- [ ] Nur Material, keine Story?
- [ ] Volatiles markiert?

# Agent 2: SEO & Outline Architect

## Rolle
Struktur/Outline + GEO-Pflichtblöcke erzwingen.

## Aufgaben
- Erzeugt Outline, die Suchintention erfüllt und "referenzfähig" ist
- Definiert feste Slots, die jedes Stück Content braucht (GEO/SEO)

## Inputs
- `01_research.md`
- Fokus-Keyword
- Cluster/Type (z.B. "How-To", "Listicle", "Guide")
- Feature-Verweis (welches Tareno-Feature passt)

## Output
- **Datei:** `02_outline.md`
- **Format:** Outline mit H2/H3
- **Pflicht:** GEO-Blöcke immer enthalten

## GEO-Pflichtblöcke (6 Stück)

### 1. TL/DR (3-5 Bullets)
- Kurzfassung für Skimmer
- Kernnutzen sofort sichtbar

### 2. Quick Definition (2 Sätze)
- Agentic Definition: "X ist Y, weil Z"
- Maschinenlesbar, zitierfähig

### 3. Named Framework/Model
- Benannt + Zweck erklärt
- Bsp: "FAKTOR-6 Methode", "BATCH-System"
- Niemals anonyme "Frameworks"

### 4. When to Use / When Not to Use
- Klare Nutzungsgrenzen
- Vermeidet falsche Erwartungen

### 5. Comparison Element
- Tabelle ODER Checkliste
- Vorher/Nachher oder Mit/Ohne

### 6. FAQ (min. 5 Fragen)
- Echte User-Fragen
- Kurze, präzise Antworten

## Hard Rules
- ❌ Keine exakten Preise/Prozentzahlen in Outline erzwingen
- ❌ Keine zweite H1 (H1 kommt später genau einmal)
- ✅ Max 12 Haupt-Sektionen (für chunkbares Writing)

## Quality Gate
- [ ] Alle 6 GEO-Blöcke vorhanden?
- [ ] Max 12 H2-Sektionen?
- [ ] Named Framework benannt?

# Agent 3: Longform Writer

## Rolle
Schreiben – aber nur auf Section-Ebene (chunkbar).

## Aufgaben
- Schreibt Section(s) gemäß Outline
- Produziert klaren, sachlichen Text (kein AI-Geschwafel)
- Baut Takeaways ein

## Inputs
- `02_outline.md`
- `01_research.md`
- Stilvorgaben (Ton: neutral-professionell; Ziel: "referenzfähig")
- Interne Regeln zu volatilen Claims

## Output
- **Datei:** `03_section_XX.md` (pro Spawn eine Section)
- **Empfohlen:** 350-600 Wörter pro Section
- **Oder:** Append in `draft.md`

## Hard Rules (Super wichtig)

### First 300 Words Rule
- **ERSTE 300 WÖRTER = factual, skimmable, non-narrative**
- Storytelling startet NUR nach:
  - Quick Definition
  - Framework introduced

### Volatile-Claim-Regel (Global)
Alles mit kurzer Halbwertszeit wird beschreibend formuliert:

| ❌ Verboten | ✅ Stattdessen |
|-------------|----------------|
| "$149 pro Monat" | "abonniert / subscription-based" |
| "67% der Nutzer" | "eine Mehrheit der Nutzer" |
| "Bis 2025" | "in der nahen Zukunft" |
| "$10K Umsatz" | "signifikantes Einkommenspotenzial" |

### Section-Struktur
- Jede Section endet mit 1-2 Takeaway-Bullets
- Genau eine H1 im gesamten Dokument
- 600+ Wörter pro H2 empfohlen

## Quality Gate
- [ ] First 300 words factual?
- [ ] Keine volatile numbers ohne Quelle?
- [ ] Takeaways am Section-Ende?
- [ ] Keine "Study shows" ohne Source?

# Agent 4: Product-Native Integration

## Rolle
Tareno-Feature sauber integrieren, ohne Werbetext.

## Aufgaben
- Findet 2-4 Stellen, wo Tareno natürlich als Workflow-Enabler passt
- Schreibt kurze Inserts + genaue Insert-Position
- Optional: 1 Screenshot-Asset vorschlagen (nur Spec, nicht erstellen)

## Inputs
- Draft-Sections (Writer Output)
- Feature/Benefit Mapping (aus Excel)

## Output
- **Datei:** `04_product_inserts.md`
- **Format:** Insert Blocks + Platzierungsanweisung

## Beispiel Insert
```
Insert 1: Nach H2 "Was kostet manuelles Posten?"
Position: Nach 2. Absatz, vor "Die Lösung"
Content:
"Wenn du merkst, dass die Planung komplexer wird als die Content-Erstellung 
selbst, ist das ein Zeichen für fehlende Struktur. Eine visuelle Pipeline 
mit Status-Tracking für jeden Post hilft hier – du siehst auf einen Blick, 
was in Planung, Review oder zur Freigabe bereit ist."
```

## Hard Rules
- ❌ Kein "Buy now", kein Sales-Pitch
- ❌ Keine unprüfbaren Produktclaims ("unlimited", "best", "fastest")
- ❌ Kein Feature-Dump – nur 1-2 relevante Features pro Artikel
- ✅ Natürliche Einbettung als Workflow-Enabler

## Quality Gate
- [ ] Max 4 Inserts?
- [ ] Keine Sales-Sprache?
- [ ] Positionen exakt definiert?

# Agent 5: Editor & E-E-A-T + Claim Hygiene

## Rolle
Qualitätssicherung, Glaubwürdigkeit, Safety gegen Halluzinationen.

## Aufgaben
- Redigiert: Klarheit, Kürze, Struktur, Wiederholungen
- Prüft E-E-A-T Signale: Autorbox, Aktualität, präzise Begriffe
- **Claim-Entschärfung:** volatile/unsichere Aussagen neutralisieren
- Fordert Quellen für harte Claims (intern)

## Inputs
- Kompletter Draft (oder mehrere Sections)
- Regeln: volatile claims, no scripts, etc.

## Output
- **Datei:** `05_edited.md`
- **Format:** "Edited Full Draft" als Markdown

## Hard Fail Checks
Wenn erfüllt → **sofort zurück an Writer/Orchestrator:**

- ❌ Mehr als eine H1
- ❌ `<script>` / JSON-LD im Markdown
- ❌ "Study/research says..." ohne Source
- ❌ Exakte Preise ohne Source
- ❌ Kein Definition-Block oder kein benanntes Framework

## Claim-Labels (für Review)

| Label | Bedeutung |
|-------|-----------|
| `[SOURCE]` | Externe Quelle (URL + Titel + Datum) |
| `[INTERNAL DATA]` | Eigene Daten (markiert) |
| `[EXPERIENCE]` | Erfahrung/Beispiel (markiert) |
| `[OPINION]` | Meinung (sparsam nutzen) |
| `[UNVERIFIED]` | Kann nicht verifizieren (last resort) |

## Strict Validation Rules

### Studies/Statistiken
- MÜSSEN haben: URL + Titel + Publication Date
- Beispiel: "67% der Creator [SOURCE: HubSpot State of Marketing 2024, hubspot.com]"

### Preise/Kosten
- MÜSSEN haben: Offizielle Pricing-Link
- Beispiel: "ScreenFlow $149 [SOURCE: telestream.net/pricing]"

### Monetarisierungs-Claims
- MÜSSEN haben: Echte Statistik/Link ODER klar als `[EXPERIENCE]` markiert
- ❌ "You can make $10K" → REJECT
- ✅ "Reports show $10K potential [SOURCE: ...]"

## Quality Gate
- [ ] Alle volatilen Claims entschärft?
- [ ] Preise/Studien mit Sources?
- [ ] Keine unverifizierten Monetarisierungs-Claims?
- [ ] E-E-A-T Signale vorhanden?

Macht den Artikel "zitierbar" (GEO) und "linkwürdig" (Backlinks), ohne Content aufzublähen.

### 1. Reference Block: "Key Take
